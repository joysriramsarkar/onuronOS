# ADR-0006: Verified Boot Trust Chain and Flashing Safety

## Status
Accepted

## Context
Flashing custom OS images to physical smartphones carries significant risk of hardware failure, unrecoverable boot loops, or bricking. Additionally, self-signed metadata descriptors do not constitute a bootloader-enforced root of trust.

## Decision
1. **Verified Boot Integrity Definition**:
   - Custom cryptographic metadata generated by `build/mkvbmeta.py` is designated as an **Integrity Descriptor Prototype**.
   - Standard Android Verified Boot (AVB 2.0) production-ready status can only be claimed when the device bootloader enforces OEM public key pinning and validates `vbmeta` signatures prior to executing the kernel.
2. **Safe Flashing Gates (`build/flash-device.sh` / `.ps1`)**:
   - The flasher strictly probes `fastboot devices`. If no device is detected, it terminates.
   - The flasher queries device identity (`fastboot getvar product`). If the device does not match the chosen target profile, flashing is blocked.
   - Flashing generic images (`aarch64-generic`) to physical phones is blocked unless explicitly overridden with `--force-unsupported`.
   - Data partition wiping (`userdata`) is opt-in (`--wipe-userdata`), never executed by default.
   - All partition images (`boot.img`, `system.img`, `vbmeta.img`) must exist and pass integrity checks before any fastboot flash command executes.

## Consequences
- Operators cannot accidentally flash incompatible generic images to real devices.
- User personal data is safeguarded during OS testing.

## Validation
- Flasher scripts exit non-zero when devices or target profiles mismatch.
- Unit tests (`build/test_mkvbmeta.py`) verify image tampering detection.
