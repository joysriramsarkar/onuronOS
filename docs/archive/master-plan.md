## ১. প্ল্যাটফর্মের মূল পরিচয় ও অলঙ্ঘনীয় নীতি (Architectural Constitution)

### ১.১ OnuronOS-এর সংজ্ঞা
**OnuronOS** হলো একটি স্বাধীন, লিনাক্স কার্নেল-ভিত্তিক, Rust-ফার্স্ট ইউজারস্পেস সমৃদ্ধ নেটিভ মোবাইল অপারেটিং সিস্টেম।

```text
Linux LTS Kernel (6.6)
       ↓
    nilinit (PID 1 / Supervisor)
       ↓
    NilHAL (Hardware Abstraction Boundary)
       ↓
Onuron Core Micro-Services (inputd, powerd, netd, audiod, nilwdt, etc.)
       ↓
runtime/nilrt (Sandbox / Namespaces / Seccomp / UID / Permissions)
       ↓
NilLang + Alap + NilUI / nilshell
       ↓
Signed Native Applications (.nilax)
```

### ১.২ অ্যান্ড্রয়েড কম্প্যাটিবিলিটির অবস্থান
- OnuronOS কোনো **AOSP fork বা Android ROM নয়**।
- Android compatibility (`android/`, `android-host/`) একটি বিচ্ছিন্ন সেকেন্ডারি সাবসিস্টেম (Isolated Container/Bridge)। এটি নেটিভ আর্কিটেকচারের ফাউন্ডেশন নয়।

### ১.৩ অলঙ্ঘনীয় ১০টি নিয়ম (Prohibited Actions)
1. প্রজেক্টকে কোনো অবস্থাতেই সাধারণ AOSP বা Android ROM-এ রূপান্তর না করা।
2. NilLang/Alap-এর পরিবর্তে Generic Web/PWA বা Android API-কে নেটিভ প্ল্যাটফর্ম না বানানো।
3. `systemd` বা `OpenRC`-কে হিডেন ডিপেন্ডেন্সি হিসেবে যুক্ত না করা (`nilinit`-ই PID 1)।
4. কোনো ডিরেক্টরি বা ডক থাকা মানেই ফিচার তৈরি হয়ে গেছে—এমন ভুয়া অনুমান না করা।
5. প্রমাণ (reproducible boot/log) ছাড়া হার্ডওয়্যার সাপোর্টের মিথ্যা দাবি না করা।
6. ফিচার চালু করার অজুহাতে স্যান্ডবক্সিং, পারমিশন, SELinux বা Seccomp বাইপাস না করা।
7. বিদ্যমান অ্যাবস্ট্রাকশনকে উপেক্ষা করে মনগড়া আর্কিটেকচারাল রিরাইট না করা।
8. অ্যান্ড্রয়েড কম্প্যাটিবিলিটি কোডকে সরাসরি নেটিভ Onuron API-এর সাথে কাপল না করা।
9. আর্কিটেকচারাল পরিবর্তন করার আগে তার ওনারশিপ লেয়ার এবং ADR ডকুমেন্টেশন নিশ্চিত করা।
10. রিয়েলিটি ক্লাসিফিকেশন কঠোরভাবে অনুসরণ করা।

## ২. রিয়েলিটি ক্লাসিফিকেশন ফ্রেমওয়ার্ক (Reality Discipline)

প্রতিটি সাবসিস্টেম এবং ফিচারকে অবশ্যই নিম্নোক্ত ৫টি স্তরের যেকোনো একটিতে চিহ্নিত করতে হবে:
1. `IMPLEMENTED`: কোড সম্পূর্ণ, টেস্ট পাস করে, বাস্তবে কাজ করে ও যাচাইকৃত।
2. `FUNCTIONAL PROTOTYPE`: মৌলিক কোড কাজ করে, তবে প্রডাকশন হার্ডেনিং বা সম্পূর্ণ ফিচার বাকি।
3. `EXPERIMENTAL`: গবেষণা বা পরীক্ষামূলক বাস্তবায়ন, ইন্টারফেস পরিবর্তনশীল।
4. `STUB / SIMULATED`: ডিরেক্টরি বা মক/সিমুলেটেড কোড আছে, আসল লজিক বাকি।
5. `PLANNED`: শুধুমাত্র ডিজাইন বা আর্কিটেকচার ডকুমেন্টে উল্লিখিত, কোনো কোড নেই।

## ৩. সাবসিস্টেম আর্কিটেকচার স্পেসিফিকেশন

### ৩.১ কার্নেল ও বুট স্পাইন (`nilinit`)
- **Kernel:** Linux LTS 6.6, 최소화된 defconfig, cgroups v2, namespaces, seccomp-bpf, SELinux সাপোর্ট।
- **Boot Chain:** Bootloader (AVB/U-Boot) → Kernel + initramfs → `nilinit` (PID 1) → NilHAL → Core Services → `nilshell`।
- **`nilinit` দায়িত্ব:**
  - প্রাথমিক মাউন্ট (`/proc`, `/sys`, `/dev`, `/run`, cgroup v2)।
  - মাইক্রো-ডেমন ডিপেন্ডেন্সি গ্রাফ (DAG) পরিচালনা ও সকেট অ্যাক্টিভেশন।
  - ক্র্যাশ হলে অটোমেটিক রিস্টার্ট (Exponential backoff) এবং হার্ডওয়্যার ওয়াচডগ পিং (`nilwdt`)।
  - Graceful Shutdown/Reboot সিকোয়েন্স (SIGTERM → SIGKILL → unmount/sync)।

### ৩.২ NilHAL (Hardware Abstraction Layer)
- ড্রাইভার ডিটেইলস উচ্চতর সার্ভিস থেকে সম্পূর্ণ আড়াল করা।
- **কোর ট্রেইটস:**
  - `DisplayDevice`: DRM/KMS মোডসেটিং, বাফার হ্যান্ডলিং।
  - `InputDevice`: evdev টাচস্ক্রিন, বাটন, কীবোর্ড ইভেন্ট।
  - `PowerSource`: ব্যাটারি স্ট্যাটাস, চার্জিং, থার্মাল জোন।
  - `AudioSink / AudioSource`: ALSA / PCM স্ট্রিম।
  - `NetworkLink`: rfkill, Wi-Fi, মডেম ইন্টারফেস।
- **ব্যাকএন্ডসমূহ:**
  - `FakeHAL`: ইউনিট টেস্ট এবং হেডলেস CI-এর জন্য মেমরি-অনলি মক।
  - `QemuHAL`: QEMU ভার্চুয়াল ডিভাইসের জন্য।
  - `RealHAL`: আসল রেফারেন্স মোবাইল হার্ডওয়্যারের জন্য।

### ৩.৩ আইপিসি এবং প্রোটোকল আর্কিটেকচার (`protocol/`)
- লোকাল ইন্টার-প্রসেস কমিউনিকেশনের জন্য সুরক্ষিত ইউনিক্স ডোমেন সকেট (`/run/onuron/...`)।
- ফ্রেম স্ট্রাকচার: Magic Bytes (`ONUR`, 4B) + Payload Length (4B) + Version (2B) + Message Type (2B) + Request ID (8B) + Flags (4B) + Payload।
- `SO_PEERCRED` / `SCM_CREDENTIALS` দিয়ে কলারের UID/GID যাচাইকরণ।
- প্রতিটি রিকোয়েস্টে টাইমআউট এবং ব্যাকপ্রেশার হ্যান্ডলিং।

### ৩.৪ কোর সিস্টেম সার্ভিসেস (Micro-Daemons)
- `inputd`: evdev থেকে ইভেন্ট পড়ে ফিল্টার করে `nilshell`-এ পাঠানো।
- `powerd`: স্টেট মেশিন (Active, ScreenOff, LowPower, Suspend, Shutdown), wakelock ট্র্যাকিং ও `nilprotocol` ফ্রেম হ্যান্ডলিং।
- `nilwdt`: হার্ডওয়্যার ওয়াচডগ ফিডার (`/dev/watchdog`), সাবসিস্টেম হেলথ চেকার এবং গ্রেসফুল ডিসআর্ম।
- `netd`: নেটওয়ার্ক ইন্টারফেস, Wi-Fi সংযোগ, DNS (`dnsd`), রাউটিং।
- `audiod`: অডিও স্ট্রিম মিক্সিং, ভলিউম এবং রাউটিং।
- `authd`: ইউজার ক্রেডেনশিয়াল, বায়োমেট্রিক, কীবোর্ড পিন যাচাই।
- `crashd` ও `logd`: সিস্টেম ক্র্যাশ ডাম্প ও সেন্ট্রালাইজড স্ট্রাকচার্ড লগিং।

### ৩.৫ অ্যাপ্লিকেশন রানটাইম ও নিরাপত্তা (`runtime/nilrt`)
- অ্যাপ স্যান্ডবক্সিং:
  - লিনাক্স নেমস্পেস: Mount (`/` রীড-অনলি, প্রাইভেট `/data/app/<id>`), PID, Network (ঐচ্ছিক), IPC, User।
  - Seccomp-BPF ফিল্টার: ক্ষতিকর সিস্টেম কল নিষিদ্ধ (যেমন `ptrace`, `kexec`, `reboot`)।
  - পার-অ্যাপ ইউনিক UID (যেমন UID 10000+)।
  - Linux Capabilities ড্রপ করা (ক্যাপাবিলিটিহীন সাধারণ প্রসেস)।
- পারমিশন ব্রোকার:
  - ক্যামেরা, লোকেশন, অডিও রেকর্ডিং ইত্যাদি সংবেদনশীল সার্ভিসে অ্যাক্সেসের জন্য সেন্ট্রাল অথোরাইজেশন ও ইউজার প্রম্পট।
- অ্যাপ্লিকেশন লাইফসাইকেল:
  - `Installed → Eligible → Starting → Running → Suspended → Stopped`।

### ৩.৬ প্যাকেজ ম্যানেজমেন্ট (`pkg/nilpkg`) ও `.nilax`
- **`.nilax` ফরম্যাট:** Ed25519 সাইনড টার/জিপ আর্কাইভ, যার মধ্যে রয়েছে:
  - `manifest.json`: App ID, নাম, ভার্সন, আর্কিটেকচার, পারমিশন তালিকা, ডিজিটাল সিগনেচার।
  - `bin/<id>` ও অন্যান্য অ্যাসেটস।
- **`nilpkg` কার্যপদ্ধতি:**
  - `nilpkg pack`: বাইনারি থেকে সাইনড `.nilax` আর্কাইভ তৈরি।
  - সিগনেচার ভ্যালিডেশন ছাড়া কোনো প্যাকেজ ইনস্টল হবে না।
  - অ্যাটমিক ইনস্টলেশন (Staging ডিরেক্টরিতে আনপ্যাক → অ্যাটমিক রিনেম)।
  - রোলব্যাক সাপোর্ট এবং ডিপেন্ডেন্সি ট্র্যাকিং।

### ৩.৭ UI ফ্রেমওয়ার্ক ও সেল (`nilshell`, `nilui`, `nilui-gpu`)
- **`nilui`:** ডিক্লারেটিভ রিঅ্যাক্টিভ UI মডেল, সিন গ্রাফ, লেআউট ইঞ্জিন।
- **`nilui-gpu`:** হার্ডওয়্যার অ্যাক্সিলারেটেড রেন্ডারিং পাইপলাইন (DRM/KMS + Vulkan/GLES/Software fallback)।
- **`nilshell`:**
  - মোবাইল কম্পোজিটর (সারফেস ম্যানেজমেন্ট ও টাচ জেসচার রাউটিং)।
  - স্ট্যাটাস বার (ব্যাটারি, নেটওয়ার্ক, সময়, নোটিফিকেশন)।
  - নোটিফিকেশন শেড, লকস্ক্রিন ও অ্যাপ লঞ্চার।
  - প্যাকেজ ম্যানেজমেন্ট ইন্টিগ্রেশন ও সরাসরি স্যান্ডবক্সড লঞ্চ (`nilrt-launch`)।

### ৩.৮ ডিস্ট্রিবিউটেড লেয়ার (`softbus`)
- লোকাল-ফার্স্ট ডিভাইস ডিসকভারি (mDNS / BLE)।
- এন্ড-টু-এন্ড এনক্রিপ্টেড ট্রান্সপোর্ট এবং কি-এক্সচেঞ্জ।
- মাল্টি-ডিভাইস স্টেট শেয়ারিং, ক্লিপবোর্ড সিঙ্ক, এবং ক্যাপাবিলিটি অথরাইজেশন।

### ৩.৯ অ্যান্ড্রয়েড কম্প্যাটিবিলিটি ব্রিজ (`android/`, `android-host/`)
- নেটিভ সিস্টেম থেকে সম্পূর্ণ আলাদা কনটেইনার/গেস্ট এনভায়রনমেন্ট।
- Wayland/EGL সারফেস শেয়ারিংয়ের মাধ্যমে Onuron Shell-এ উইন্ডো প্রদর্শন।
- ইনপুট ফরোয়ার্ডিং, অডিও সিঙ্ক ব্রিজ, এবং ব্যাকগ্রাউন্ড রিসোর্স নিয়ন্ত্রণ।

### ৩.১০ স্টোরেজ, সিকিউরিটি ও OTA
- **স্টোরেজ লেআউট:** `/system` (Read-only, dm-verity), `/vendor` (Read-only), `/data` (Encrypted, fscrypt/LUKS, Read-Write)।
- **ক্র্যাশ সেফটি:** অ্যাটমিক ফাইল রাইট হেল্পার (`write_atomic` via tempfile + fsync + rename)।
- **সিকিউরিটি পলিসি:** SELinux Enforcing পলিসি এবং ফাইল কনটেক্সট।
- **OTA:** A/B ডুয়াল স্লট ট্রানজ্যাকশনাল আপডেট, স্বয়ংক্রিয় রোলব্যাক যদি বুট ব্যর্থ হয়।

## ৪. বাস্তবায়নের দীর্ঘমেয়াদি পর্যায়ক্রম (Implementation Phases)

```text
[Phase 0: অডিট ও গভর্নেন্স] (সম্পন্ন)
       ↓
[Phase 1: বুট স্পাইন ও nilinit/nilwdt হার্ডেনিং] (সম্পন্ন)
       ↓
[Phase 2: আইপিসি প্রোটোকল ও NilHAL স্ট্যান্ডার্ডাইজেশন] (FakeHAL ও nilprotocol সম্পন্ন)
       ↓
[Phase 3: কোর ডেমন ও সিমুলেটর/হার্ডওয়্যার ইন্টিগ্রেশন] (চলমান)
       ↓
[Phase 4: নেটিভ অ্যাপ্লিকেশন ইকোসিস্টেম (nilrt + nilpkg + .nilax + nilshell)] (ভাঙ্গা স্লাইস সম্পন্ন)
       ↓
[Phase 5: অ্যান্ড্রয়েড কম্প্যাটিবিলিটি ব্রিজ]
       ↓
[Phase 6: সিকিউরিটি এনফোর্সমেন্ট, SELinux ও OTA]
```
