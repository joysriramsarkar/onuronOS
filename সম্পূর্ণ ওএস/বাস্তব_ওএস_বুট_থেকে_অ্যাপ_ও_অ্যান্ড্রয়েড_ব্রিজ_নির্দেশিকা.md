# OnuronOS: বাস্তব বুট থেকে পূর্ণ নেটিভ সিস্টেম

এই নথি OnuronOS-এর জন্য একক বাস্তবায়ন নির্দেশিকা। লক্ষ্য হলো Linux LTS → `nilinit` → NilHAL → Onuron service → `nilrt` → NilLang/Alap/NilUI → signed `.nilax` অ্যাপ—এই native spine সম্পূর্ণ করা এবং Android compatibility-কে `android/`, `android-host/`, `nilandroidd`-এর আলাদা subsystem হিসেবে রাখা।

## সত্যতা ও বর্তমান অবস্থা

কোনও নথি লিখলেই physical phone support তৈরি হয় না। এই repository-র `docs/maturity.toml` অনুযায়ী QEMU boot, init, storage, IPC, sandbox, package tooling ইত্যাদি `functional-prototype`; Android compatibility, terminal, browser এবং কয়েকটি hardware service এখনও stub/experimental বা simulated fallback ব্যবহার করে। তাই production release-এ fabricated data, fallback frame বা fake modem ঢুকবে না। কোনও সার্ভিস hardware না পেলে `UNAVAILABLE` status দিয়ে ব্যর্থ হবে।

প্রতিটি milestone-এর প্রমাণ তিনটি জিনিসে থাকবে: source path, automated test, এবং target-এর boot/runtime log। Evidence ছাড়া `IMPLEMENTED` লেখা যাবে না।

## ১. মালিকানা ও boot contract

| স্তর | repository path | দায়িত্ব | release gate |
|---|---|---|---|
| Kernel/bootloader | `kernel/`, `targets/`, `build/mkbootimg.py` | Linux LTS, DTB, verified boot | signed image, reproducible hash |
| PID 1 | `nilinit/` | mount, policy load, service supervision | PID 1 survives service crash |
| Hardware boundary | `runtime/nilhal/`, `hal/` | capability/error contract | no app imports `/sys` or `/dev` |
| IPC | `protocol/` | versioned framed messages | malformed frame rejected |
| Services | `services/` | one privilege/domain per daemon | health socket + restart policy |
| Runtime | `runtime/nilrt/` | identity, namespaces, seccomp | sandbox escape tests pass |
| Native apps | `runtime/nillang/`, `alap/`, `apps/`, `pkg/nilpkg/` | compile/sign/install/launch | signature and permission checks |
| Shell | `shell/`, `runtime/nilui*` | compositor, launcher, terminal | real daemon data only |
| Android | `android/`, `android-host/`, `services/nilandroidd/` | isolated guest/host bridge | guest lifecycle + adb tests |

Boot sequence must be deterministic:

```text
firmware → signed boot.img → Linux LTS → initramfs → /sbin/nilinit
→ mount /proc /sys /dev /run → load SELinux enforcing
→ unlock/mount /data → start NilHAL-backed daemons
→ start compositor/nilshell → OOBE or lockscreen → launcher
```

`nilinit` must fail closed: missing mandatory mount, policy, signature key, or service contract stops normal boot and enters recovery. Do not silently start a demo shell.

## ২. reproducible toolchain ও QEMU gate

Linux build host-এ Rust toolchain, clang/LLVM, Linux kernel tools, `qemu-system-x86_64`, `qemu-system-aarch64`, `mtools`, `cpio`, `xz`, `openssl`, `dtc`, `avbtool`/project equivalent এবং SELinux `checkpolicy` নির্দিষ্ট version-এ pin করুন। Windows development-এর জন্য WSL2 ব্যবহার করুন; host shell-এ image বানিয়ে physical flash করবেন না।

```sh
git clean -xfd   # শুধুমাত্র disposable clone-এ
rustup show
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
python3 build/gen-maturity.py --check
python3 build/test_mkbootimg.py
python3 build/test_mkinitramfs.py
python3 build/test_mkvbmeta.py
python3 build/test_qemu_smoke.py
```

প্রথম target `qemu-x86_64`; পরে `qemu-aarch64`। Existing scripts (`build/qemu-boot.sh`, `build/qemu-persistence-test.py`, `build/mkdisk.py`, `build/mkinitramfs.py`) পুনঃব্যবহার করুন। image builder-এর ন্যূনতম contract:

```sh
set -euo pipefail
target="${1:?target required}"
cargo build --workspace --release
python3 build/mkinitramfs.py --nilinit target/release/nilinit --out out/initramfs.cpio.gz
python3 build/mkdisk.py --target "$target" --out out/disk.img
python3 build/mkvbmeta.py --boot out/boot.img --system out/system.img --out out/vbmeta.img
sha256sum out/*.img > out/SHA256SUMS
```

QEMU acceptance: cold boot, 60-second health window, compositor visible, `nilinit` PID 1, all mandatory services healthy, reboot persistence, package install/launch, SELinux enforcing, seccomp active, and no `SIMULATED` user-facing value.

## ৩. nilinit ও filesystem

`nilinit`-এ explicit mount table ব্যবহার করুন: read-only `/system`, read-only `/vendor`, writable encrypted `/data`, tmpfs `/run`, `devtmpfs /dev`, `proc /proc`, `sysfs /sys`, cgroup v2। Service unit-এ `exec`, `user`, `group`, `restart`, `after`, `socket`, `capabilities`, `selinux_domain` fields version করুন। Shell থেকে arbitrary command নিয়ে PID 1 spawn করা যাবে না।

```rust
// nilinit/src/contract.rs: mandatory service health rule
pub fn require_health(path: &std::path::Path, service: &str) -> std::io::Result<()> {
    let state = std::fs::read_to_string(path)?;
    if state.trim() != "READY=1" {
        return Err(std::io::Error::new(std::io::ErrorKind::Other,
            format!("{service} is not ready")));
    }
    Ok(())
}
```

Crash loop backoff, watchdog, dependency ordering এবং recovery shell test করুন। `systemd`/`OpenRC` যোগ করবেন না।

## ৪. NilHAL ও real hardware services

প্রতিটি capability-র ফল `Ok(value)`, `Unavailable(reason)`, `PermissionDenied`, বা `Io(error)` হবে। FakeHAL কেবল unit/integration test-এ থাকবে; production image-এ নয়। `powerd` `/sys/class/power_supply`, `inputd` evdev, `netd` netlink, `audiod` ALSA, `camerad` V4L2, `btd` BlueZ D-Bus, `telephonyd` vendor modem transport, display `DRM/KMS` ব্যবহার করবে। Hardware অনুপস্থিত হলে service READY হবে না এবং UI-তে `Unavailable` দেখাবে।

```rust
pub enum HalError { Unavailable(String), PermissionDenied, Io(std::io::Error) }
pub trait Battery { fn snapshot(&self) -> Result<BatteryState, HalError>; }
pub struct BatteryState { pub percent: u8, pub charging: bool, pub millivolts: u32 }
```

Real device bring-up-এ DTS/DTB, regulator, clocks, GPIO, firmware, panel, touch, codec, camera sensor, modem এবং Wi-Fi/BT firmware আলাদা evidence সহ enable করুন। Driver file থাকা hardware support-এর প্রমাণ নয়।

## ৫. IPC, identity ও security

`protocol/`-এর length-prefixed, versioned frame-এ magic, version, message type, payload length, request id এবং authenticated peer identity রাখুন। সকল Unix socket `/run/nilos/*.sock`; permissions ও SELinux labels install-time-এ বসবে।

Native app launch pipeline:

```text
nilpkg verify signature → manifest/schema validate → allocate app UID
→ mount private root → namespace (user,pid,mnt,ipc,uts,net as policy)
→ drop groups/caps → install seccomp → exec through nilrt
```

SELinux enforcing, fscrypt data, seccomp default-deny এবং namespace tests বাধ্যতামূলক। Permission broker ছাড়া camera/mic/network/storage খুলবেন না। `runtime/nilrt/src/sandbox.rs`-এর TODO বা no-op `install_seccomp` release gate-এ ব্যর্থ হবে।

```sh
getenforce                 # Enforcing আবশ্যক
cat /proc/1/status         # nilinit PID 1
grep Seccomp /proc/<pid>/status
unshare --user --pid --mount-proc true
```

## ৬. `.nilax` package ও একটি native app

Manifest-এ app id, version, ABI, entrypoint, declared permissions, content hash, signer key id রাখুন। Ed25519 signature verify না হলে install atomicভাবে বাতিল হবে।

```sh
nilpkg pack --manifest app.toml --root root/ --key keys/dev.ed25519 --out Notes.nilax
nilpkg verify Notes.nilax --trust /etc/onuron/keys/trusted
nilpkg install Notes.nilax
nilrt launch org.onuron.notes
```

একটি end-to-end app দিয়ে প্রমাণ করুন: NilLang source compile, Alap state/lifecycle, NilUI scene, service IPC, permission prompt, crash/restart, uninstall এবং rollback।

## ৭. shell, terminal ও browser

`nilshell` compositor-এ DRM/KMS framebuffer, evdev input এবং real clock/power/network snapshots bind করুন। `shell/src/simulated.rs`-এর screens production build থেকে বাদ দিন; test fixture হিসেবে রাখলে feature flag দিয়ে compile করুন।

টার্মিনাল privileged shell নয়। `nilshell-terminal` PTY তৈরি করবে, user UID/namespace-এ `/bin/sh` চালাবে, audit করবে এবং `/proc`, `/sys` read policy অনুযায়ী প্রকাশ করবে। `ps`, `mem`, `net`, `disk` প্রতিটি command kernel API বা service socket থেকে পড়বে।

ব্রাউজার native app boundary-তে sandboxed WebKitGTK/WPE বা target-এ port করা অন্য maintained engine ব্যবহার করবে; engine, TLS CA store, downloads, cookies, GPU process এবং site isolation আলাদা policy-তে থাকবে। Engine না port হওয়া পর্যন্ত launcher-এ Browser icon থাকবে না এবং status `PLANNED` থাকবে।

## ৮. Android bridge (আলাদা compatibility subsystem)

Native app model-এ Android API ঢোকাবেন না। `nilandroidd` শুধু lifecycle, display/input/audio/network/storage capability proxy করবে। Guest choice (container/VM) ADR-এ স্থির না হওয়া পর্যন্ত implementation-এ hard-code করবেন না।

প্রয়োজনীয় ধাপ:

```text
signed Android guest image → isolated namespaces/cgroup/device allowlist
→ binder/ashmem এবং required HAL endpoints
→ nilandroidd control socket
→ guest boot health → package install → activity launch
→ input/display/audio/network round-trip → clean stop/restart
```

Host side (`android-host/`) কেবল explicit capability contract মেনে JNI/transport করবে। `adb` bridge-এ host TCP port expose করবেন না; Unix socket, authenticated pairing key এবং per-device authorization ব্যবহার করুন। APK install test:

```sh
nilandroidctl start
nilandroidctl wait-ready --timeout 120
nilandroidctl adb devices
nilandroidctl install ./fixtures/calculator.apk
nilandroidctl launch com.example.calculator
nilandroidctl screenshot --out evidence/android-launch.png
nilandroidctl stop
```

Guest না উঠলে placeholder screen দেখাবেন না; error, logs এবং retry action দেখাবেন।

## ৯. QEMU থেকে reference phone

প্রথমে QEMU evidence সম্পূর্ণ করুন। এরপর একটি নির্দিষ্ট reference device (বর্তমান ADR অনুযায়ী OnePlus Fajita/নির্বাচিত board) বেছে bootloader unlock, signed boot/vbmeta, partition map, vendor firmware, DTB এবং recovery path নথিবদ্ধ করুন। Generic fastboot command কপি করবেন না; `build/target_registry.py`-র exact target ছাড়া flasher fail করবে।

Bring-up order: serial console → kernel/storage → display/touch → input → power/thermal → Wi-Fi/BT → audio → camera → modem → suspend/resume → verified A/B update। প্রতিটি ধাপে boot log, dmesg, service health JSON, manual test এবং rollback evidence সংরক্ষণ করুন।

Release checklist: reproducible image hash; signed boot/system/vendor/vbmeta; QEMU cold/reboot/persistence; nilinit crash recovery; SELinux enforcing; sandbox escape denial; `.nilax` signature; terminal real PTY; browser page load; Android guest install/launch; physical device matrix; OTA rollback। এই সব pass না করা পর্যন্ত “real phone-এ সব চলে” দাবি করা যাবে না।
